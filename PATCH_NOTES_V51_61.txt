Betonshchik v51.61 — FINAL scene + mobile crash hardening + menu music + debug

Scene:
- Uses user-provided FINAL.glb as the new source of truth.
- Desktop FINAL scene is byte-preserved and split into <=20 MiB .bin files for Cloudflare.
- Desktop textures are not downscaled/recompressed by this patch.
- Mobile FINAL scene has a normal memory profile (~212 MiB decoded scene textures) and automatic SAFE profile (~101 MiB decoded scene textures).
- SAFE profile also uses 1024px player/NPC base textures.

Mobile crash hardening:
- THREE.Cache disabled on touch devices so external .bin/image payloads are not retained after upload.
- EffectComposer/postprocess render targets are no longer allocated on mobile at all.
- Main renderer MSAA disabled on mobile; desktop rendering stays unchanged.
- Shop preview WebGL context is created lazily only when the shop preview is actually rendered.
- FPS player load is deferred until the scene is ready instead of loading concurrently with the giant scene.
- NPC loading is delayed after scene upload to reduce peak memory.
- If normal mobile loading fails/context is lost, next attempt automatically uses FINAL_MOBILE_SAFE.gltf.
- If the browser dies during scene/player/NPC loading, the next launch detects the unfinished boot stage and enables SAFE mode.

Debug:
- Small DBG button on mobile opens device/GPU/boot-stage/error log.
- Boot stages persist in localStorage so hard crashes can be diagnosed on the next launch.
- Add ?fullmobile=1 to force the normal mobile profile for testing.

Audio:
- Main soundtrack now attempts to play in the main menu immediately.
- If browser autoplay policy blocks audio, the first tap/swipe/key anywhere in the menu starts it; PLAY is no longer required.

Baba Kapa:
- FINAL exports Baba as separate named meshes; runtime reconstructs a BabaKapa group from those parts so interaction/ground locking continues to work.

Cloudflare:
- Verified: 0 deployment files exceed 25 MiB.
